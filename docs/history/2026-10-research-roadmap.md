# 研究路线图

> 项目方向以本文为准；做到哪、下一步做什么见 `docs/status.md`。  
> 2026-10-19 初版，2026-10-20 合并产品负责人与另一 AI 的两份讨论稿后重写；2026-10-21 第 4 节改为激进 / 保守定义并加收尾标准。

## 1. 目标

**从职业 CS2 Demo 中找出普通玩家可以学、可以练、可以验证的行为规律。**

每条规律要回答四个问题：
1. **发现了什么**：什么局势下，职业选手倾向于怎么做？
2. **证据是什么**：样本量、行为分布、结果对比、可回放的片段和反例。
3. **为什么值得学**：在可比的局势里，这种做法是否稳定地和更好的结果相关？
4. **普通玩家怎么练**：一个能执行、能衡量、练完能复盘验证的动作。

**北极星指标**：经人工核验、带 Demo 证据的**行为规律卡**数量（第 5 节）。"证据不足"、"不支持"这样严谨的否定结果也算产出。

**不做**：新增基本功评分、排行榜、综合评分、复杂前端；行为总分、胜率模型（ΔWP）、强化学习；让 AI 推断选手意图或自己总结规律。基本功指标保留，只作控制变量和辅助解释。

## 2. 研究原则

1. **分析单位是"局势中的某个玩家"的一段行为**，有开始和结束时刻；tick 只是采样点，不等于一次决策。观察起点放在行为真正开始的时刻（例如连续击杀结束之后）
2. **每个样本可追溯**：`demo_id`、`round_id`、`player_id`、`start_tick`、`end_tick`，能在游戏里跳转回放
3. **玩家视角与全局视角分开**：行为定义和"玩家知道什么"只用玩家可能获知的信息（几何视野、本队雷达、能听到的声音；语音未知）；控制混杂变量和计算结果可以用 Demo 里的真实状态
4. **行为、结果、解释三者分开**：不用结果反向定义行为；推断性的字段默认为空，不能写成测量出来的事实
5. **缺数据记 `null` / `unknown`**，不编造
6. **只用行为之前的状态分层和匹配**，不用行为之后的变量；保留地图、阵营、时间、人数、经济、区域、队友支援、赛事级别等混杂变量
7. **样本不独立**：同一回合、同一场比赛、同一支战队的样本相关，统计按比赛聚类；结论要说明是否跨多支队伍、多个赛事都成立
8. **因果保守**："职业选手常这么做"不等于"这么做更好"；警惕反向因果（"赢了所以这么打"）；职业比赛里有效的做法不一定适用于路人局
9. **自动标签必须人工抽样复核**，记录错误类型；阈值都放在 `config/`，复核前只是工程假设

## 3. 研究方法

### 3.1 一条研究的流程

触发局势 → 行为窗口 → 行为标签 → 人工复核标签 → 记录后果 → 在可比局势中比较 → 找典型片段和反例 → 写规律卡

### 3.2 后果怎么记

分维度记录，**不打总分**。一次后撤可能同时减少暴露、改善补枪条件、放弃前沿信息，不能简单记成"好"或"坏"。

| 维度 | 例子 | 现状 |
|---|---|---|
| 局势优势 | 交火后几秒内是否被补、人数变化 | 在用 |
| 资源 | 血量、道具、弹药 | 在用 |
| 信息 | 交火后对手还能不能看到他 | 下一步，用已有的几何视野 |
| 空间控制 | 控制或放弃了哪些区域、枪线 | 暂缓，需要新的几何模块 |
| 团队协同 | 队友能否补枪、交叉火力 | 暂缓，需要新的几何模块 |

- 当前假设用不到的维度记 `null`；每个值注明是直接读取（`observed`）、估计（`estimated`）还是推断（`hypothesized`）
- 区分"在窗口内发生了"和"能归因于这次行为"
- 时间窗口是可调参数，放在配置里，要做敏感性分析

### 3.3 结论分三级

1. **描述**：行为前后发生了什么
2. **相似局势比较**：行为与结果的关联。**第一张规律卡最多写到这一级**
3. **反事实验证**：受控训练、专家评估（以后再做）

### 3.4 分工

| | 负责 |
|---|---|
| 程序 | 解析、行为窗口、能写成规则的标签、后果数值、样本匹配、Demo 引用 |
| AI | 只判写不成规则、要看过程和上下文的行为；输入只给玩家视角，不给回合结果。以后再根据已验证的规律卡讲解和给练法 |
| 人工 | 复核标签和行为边界，检查有没有用到玩家不可能知道的信息，找反例，判断教学价值 |

R03 的教训：AI 和规则高度一致，只说明它在按同一套规则重算，不能证明定义对。定义对不对只能靠人工复核。

## 4. 当前研究：Mirage CT 拿下首杀之后

**范围**：Mirage，CT，局势从 5v5 变成 5v4。已有 189 场职业比赛、2430 个首杀选手窗口（`data/research/stance/st-2`）。

**主线**（2026-10-21 更新）：**拿下首杀的 CT，交战结束后的 3 秒内是激进还是保守？这两种做法的后果有什么不同？**
- 行为（产品负责人定）：
  - **激进·主动寻求对枪**：往敌人方向走、去拉新的枪线
  - **激进·被动寻求对枪**：停在能架到敌人来路的位置等人
  - **保守**：换到更安全的位置、躲进掩体或烟后
  - **看不出**：交战中阵亡、观察不足 1 秒、首杀前已下包等
- 假设（待产品负责人确认）：激进的选手接下来更容易被补掉，但也更常拿到下一个击杀；这个权衡随位置角色和武器不同
- 后果分维度记（3.2）：交战后到阵亡的时间（资源）、之后是否再拿击杀（局势优势）
- 分组：位置角色（A 主防 / B 主防 / 中路 CT 侧 / 后方 / 接触区）× 武器（狙击枪 / 其他）
- 定义与复核记录：`docs/tasks/research/R03-ai-post-fight-reposition.md`；判定 `src/cs2coach/research/stance.py`，参数在 `config/research.toml` 的 `[research.stance]`

**当前定义**（2026-10-21 冻结）：第 6 版 + 补丁（全量 `st-6d`）。新样本盲审 25/30、留出集 29/35（都是 83%），AI（MiMo）盲审只有 73～77%，所以主线用程序标签，AI 标签用于稳健性检验
- 原位（移动 < 200、高度变化 < 60）→ 被动寻求对枪；移动后这一回合的威胁危险度升高 → 主动；危险度下降或横移 → 保守
- 补丁：一直打到回合结束 → 激进；横移但往 T 方向走 → 激进（"身边有烟 → 保守"在新样本上错多对少，已关闭）
- 开发集（35 条）大类 32/35；这些阈值是看着开发集定的，结果偏乐观

**接下来**：
1. ~~定稳行为定义~~（2026-10-21 完成，见上）：用没看过的新样本盲审复核
   - **收尾标准**：新样本上程序与人工的大类一致率 ≥ 80%，就冻结定义，进入第 2 步；达不到，只修错得最多的那一类，再测一次
   - 冻结前，在 gold-1 留出集上测一次，结果如实记录，之后不再用留出集调参数
2. 分析：
   - 用"交战后到阵亡的时间"（生存分析，回合结束时截断）代替固定"5 秒内是否被补"，解决行为期和被补期重叠的问题
   - 正对照：先确认血量、附近敌人数这类肯定有影响的变量，在这套分析里能显示出预期效应
   - 稳健性：同一分析用 AI 标签再算一遍；标签的随机错误只会让差别变小，要防的是与结果或局势相关的错误
   - 机制检验：激进的选手，对手是否更容易再看到他
3. 写第一张规律卡（支持、不支持、证据不足都可以）——草稿 `docs/cards/01-first-kill-aggression.md`（2026-10-22，典型片段待人工确认）
4. 用到产品负责人自己的 demo：找出他拿首杀的时刻，看他的行为和后果

**研究分支**（2026-10-21）：把行为再细分为主动 / 被动寻求对枪、主动 / 被动保守四类，并另记"能不能跑"的局势变量（位置角色、退路是否被看着、敌我人数、离掩体的距离）。主线结果不变，分支在主线定义冻结后开工。方案：`docs/tasks/research/R06-escape-four-class.md`

### 4.1 扩展方式：行为定义一次，局势作为分组变量

慢的是**定义并人工验证一个行为**，不是换局势。所以不再一个局势开一个课题：

1. 首杀选手上定稳的行为（交战后激进 / 保守），推广到**所有交火结束**：任意阵营、人数、回合阶段。样本从几百增加到几千
2. 阵营、人数、位置角色、武器、回合时间等都作为数据表的列，分组比较，不再单独立项
3. **先筛选、再确认**：按比赛把数据分成两半。用筛选集自动列出"激进与保守结果差别大、样本够"的局势；只在确认集里也成立的才算发现，再做人工核实、找反例、写规律卡。同时比较几十组，总会有碰巧差别大的，筛选结果只算候选
4. 推广到新局势时，抽少量样本复核行为定义在新局势下是否仍然判得准（例如 T 方进攻时）
5. 下一个需要慢功夫的是**新的行为**（补枪、道具时机等），不是新的局势

## 5. 交付物：行为规律卡

```markdown
# 行为规律：<名称>

- 状态：探索中 / 有初步证据 / 已复核 / 暂不支持
- 表述（可证伪）：在什么局势下，什么行为与什么结果相关
- 场景：地图、阵营、区域、人数、时间、支援条件
- 行为定义：时间边界、判定方法、人工复核一致率
- 数据：比赛数、回合数、样本数；战队和赛事分布
- 结果比较：分组方式、各维度后果、按比赛聚类的区间
- 局限：混杂因素、看不到的语音和战术安排、反向因果
- 典型片段 / 反例：demo_id、round_id、tick 起止
- 给普通玩家的建议、练法、练完怎么验证
```

只凭一段精彩操作、一个回合的胜负或模型的主观解释，不能写成规律卡。

## 6. 之后的方向（按顺序）

1. 同一行为推广到 Mirage 的所有交火，筛选 + 确认（4.1）
2. 新的行为（每个只定义、验证一次，再按 4.1 推广）：补枪、清点、道具时机、成功防守后前压
3. 更细的上下文：地图小位置（区分"继续压"需要）、枪线、道具、队友配合
4. 与普通玩家样本对比：相似局势下行为有什么差异，职业做法是否适用
5. 扩展到其他地图，检验规律能否推广
6. AI 讲解：只根据已验证的规律卡和证据讲解、给练法
7. 训练效果评估：玩家练完后，相关局势里的行为和结果是否改变

## 7. 立项门槛

新增任何指标、模块或可视化之前，先回答：
1. 它回答哪个游戏行为问题？
2. 它检验哪条可证伪的假设？
3. 有了结果，普通玩家能做什么？
4. 结果成立或不成立，研究下一步怎么变？

答不清楚就先不做。纯工程基础设施要说明它服务于哪项已批准的研究。
