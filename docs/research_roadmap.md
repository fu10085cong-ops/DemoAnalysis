# CS2 职业选手 Demo 行为研究项目：方向重构与最小研究闭环

> 文档定位：项目研究方向、模块优先级与近期实施路线图  
> 当前阶段：已有基本功指标，具体实现清单待盘点  
> 核心原则：**以研究问题驱动数据提取，而不是以能够提取的数据驱动功能扩张。**

## 1. 背景与问题诊断

项目初衷是从顶尖 CS2 选手的 Demo 中挖掘普通玩家可以学习的行为规律，但开发过程逐渐偏向急停、预瞄、定位、反应、击杀表现等基本功指标的收集与汇总。

这些数据不是无用，而是角色需要调整：**基本功数据应作为行为研究的基础特征、辅助解释或控制变量，不再是项目主要交付物。**

当前风险：

- 指标不断增加，却缺少明确的研究问题。
- 能描述选手「打得怎么样」，但难以说明「为何这样做、什么情况下适合这样做」。
- 从结果倒推意图，容易受到回放全知视角和幸存者偏差影响。
- 缺少可复核的 Demo 片段、反例及适用条件，难以形成可靠教学建议。

## 2. 项目重新定位

### 2.1 项目定义

**基于职业选手 Demo 的可迁移行为规律发现系统。**

从职业比赛中识别具有重复性、可解释性和可训练性的行为模式，结合相似局势和普通玩家样本检验其适用性，最终输出有证据支持的教学建议。

### 2.2 核心研究问题

每项研究应尽可能回答四个问题：

1. **发现了什么？** 在什么局势中，职业选手倾向于采取什么行为？
2. **证据是什么？** 样本量、行为分布、结果对比、可复核片段和反例分别是什么？
3. **为什么值得学习？** 控制关键局势差异后，行为与有利结果是否存在稳定关联？
4. **普通玩家怎么练？** 哪一项行动可执行、可衡量、可在训练后复盘验证？

### 2.3 三层研究体系

| 层次 | 内容 | 要回答的问题 | 在项目中的角色 |
| --- | --- | --- | --- |
| L1 基本功与表现数据 | 坐标、速度、视角、预瞄、急停、击杀等 | 玩家表现与操作水平如何？ | 基础数据 / 辅助特征 |
| L2 情境化行为模式 | 站位调整、清点、前压、后撤、配合、道具时机 | 玩家在什么条件下做了什么？ | 核心分析对象 |
| L3 可迁移的决策规律 | 行为与结果的关联、适用条件、反例和训练方案 | 为什么值得学？怎样学？ | 最终研究产出 |

**北极星指标：** 成功产出多少条经人工核验、带真实 Demo 证据、适用条件和训练方法的行为规律，而不是累计实现多少个指标。

> 「职业选手经常这么做」并不等于「这么做会提升胜率」。对观察性数据的因果解释必须保守。

## 3. 现有模块处置策略

由于尚无代码和具体指标清单，下表是建议的初步归类，需在实际仓库盘点后调整。

| 模块 | 决策 | 处理方式 |
| --- | --- | --- |
| Demo 解析和 Tick 提取 | **保留** | 保持稳定，避免重写 |
| 坐标、速度、视角、血量、武器、回合事件 | **保留** | 形成统一输入结构 |
| 急停、预瞄、定位、反应等基本功指标 | **保留但冻结扩展** | 作为后续研究特征，不再新增评分项 |
| 总评分、排行榜、精美报告 | **暂停** | 不是当前研究瓶颈 |
| 行为片段提取 | **优先新增** | 可按事件回溯前后 Tick，并定位 Demo |
| 局势上下文重建 | **优先新增** | 时间、人数、区域、支援条件、信息状态 |
| 相似局势检索及分层对比 | **优先新增** | 将行为比较建立在可比条件上 |
| 人工抽样复核和反例记录 | **优先新增** | 避免错误标签与虚假规律 |
| LLM 自动战术解读 | **后置** | 仅对已验证的结构化证据做解释 |
| 复杂 UI / 全地图平台 | **暂停** | 第一版用表格、简单可视化、Demo 跳转即可 |

### 3.1 建议进行一次代码盘点

为每个现有指标记录：

- 名称和实现文件路径；
- 输入依赖（原始事件、Tick、地图数据等）；
- 输出粒度（每 Tick / 交火 / 回合 / 玩家 / 比赛）；
- 有无单元测试、边界情况和精度验证；
- 可否作为 L2/L3 的上下文变量；
- 结论：保留、冻结、归档或需要修复。

不要因为已投入开发时间就继续扩展一个缺乏研究用途的指标。

## 4. 目标技术架构

```text
职业 Demo / 普通玩家 Demo
            |
            v
[数据基础层：已有系统]
解析器、事件、Tick、玩家状态、基本功特征
            |
            v
[局势与行为建模层：当前重点]
Situation / 行为窗口 / 上下文信息 / 行为标签
            |
            v
[行为研究引擎：当前重点]
局势分层与匹配 / 行为分布 / 结果对比 / 反例 / 置信度
            |
            v
[证据层：不可省略]
原始 demo_id + round_id + tick 区间 + 人工复核记录
            |
            v
[教学与大模型层：后续]
基于证据的解释 / 适用条件 / 训练任务 / 个人对比
```

可继续利用已有 Demo 解析能力；若需要参考成熟工具，可查看：

- [demoparser2](https://github.com/LaihoE/demoparser)
- [Awpy](https://github.com/pnxenopoulos/awpy)

### 4.1 数据设计原则

1. **以「局势中的某个玩家」而不只是「玩家整场均值」为分析单元。**
2. 保存可回放证据：`demo_id`、`round_id`、`player_id`、`start_tick`、`end_tick`。
3. 区分**比赛真实状态**与**玩家当时可能知道的信息**；不能把 Demo 上帝视角直接当作玩家信息。
4. 区分行为标签、后续结果和解释性假设，不要用结果反向定义行为。
5. 缺少数据时记录 `null` / `unknown`，不要编造。
6. 保留地图、阵营、时间、人数、经济、区域、队友支援等重要混杂变量。
7. 比赛、回合、战队和玩家样本存在相关性；不能把所有 Tick 当作独立样本。

### 4.2 Situation 数据结构草案

```json
{
  "demo_id": "match_001",
  "round_id": 12,
  "tick": 34210,
  "player_id": "player_001",
  "map": "de_mirage",
  "side": "CT",
  "alive_teammates": 5,
  "alive_enemies": 4,
  "time_remaining_s": 62.5,
  "player_position": [110, -850, 12],
  "player_health": 87,
  "weapon": "m4a1_s",
  "teammate_positions": [],
  "known_enemy_information": [],
  "action_labels": [],
  "outcome": null
}
```

*以上仅为结构示例，坐标及其余数值不是实际比赛数据。*

推荐另设 `BehaviourWindow`、`EvidenceClip`、`Annotation`、`Finding` 等模型，避免把所有业务逻辑塞进一个表。

## 5. 第一个最小研究闭环：CT 形成 5v4 后的行为调整

### 5.1 研究问题

**职业选手在 CT 从 5v5 获得首个人数优势（5v4）后，短时间内会怎样调整位置与接战方式？**

目标是先可靠识别**情境—行为—结果**，而不是一开始就证明某个战术动作必然提高胜率。

### 5.2 第一版研究边界

| 项目 | 初期限定 |
| --- | --- |
| 地图 | Mirage |
| 阵营 | CT |
| 触发事件 | CT 首次从 5v5 转为 5v4 |
| 观察时长 | 触发后 5 秒（工程假设，可随后做敏感性分析） |
| 分析单位 | 在触发时存活的 CT 玩家行为窗口 |
| 行为类别 | 保持位置、后撤、前压、横向调整 |
| 辅助标签 | 道具使用、与队友汇合、发生接战 |
| 短期结果 | 5 秒内死亡、是否失去人数优势、后续接战 |
| 长期结果 | 回合胜负（辅助，不直接当作行为因果效果） |
| 首批数据 | 20–30 场职业 Demo 作为开发/探索样本，数量不代表统计充分 |

### 5.3 行为标签定义原则

- **保持位置：** 在窗口内位置变化较小，未明显进入新的区域。
- **后撤：** 向事先定义的防守纵深/相对安全区域移动。
- **前压：** 向预先定义的潜在敌方接触区域推进。
- **横向调整：** 明显改变站位，但未满足推进或后撤定义。

这些定义是**待实现的操作性定义**，必须结合地图区域与方向信息，不能简单用 X/Y 坐标的增减判定。阈值需通过人工标注与抽样回放校准。无法判断时允许 `unknown`，辅助标签可与主要行为共存。

### 5.4 最小研究表

| 字段 | 作用 |
| --- | --- |
| `demo_id`, `round_id`, `player_id` | 来源定位和重复样本处理 |
| `start_tick`, `end_tick` | 精确回放片段 |
| `map`, `side`, `region` | 局势分层 |
| `time_remaining_s` | 控制回合阶段 |
| `teammate_distance` | 近似支援条件；不等同可补枪性 |
| `known_enemy_region` | 玩家可能掌握的敌方信息，不确定时为 unknown |
| `action_labels` | 可复核的行为描述 |
| `next_5s_result` | 行为后短期结果 |
| `round_result` | 回合结果 |
| `label_confidence` | 自动标注置信度 |
| `review_status` | 是否已人工核验 |

### 5.5 分析流程

1. **识别事件：** 提取符合定义的 CT 5v4 触发点。
2. **生成窗口：** 为存活 CT 玩家提取事件后 5 秒的移动、视角、道具及接战轨迹。
3. **赋予标签：** 使用透明规则分类，记录 `unknown` 和多标签情况。
4. **人工核验：** 随机抽样及针对边界样本回放，记录错误类型与混淆矩阵。
5. **分层比较：** 至少按回合时间、地图区域、队友支援情况拆分行为分布。
6. **检查结果：** 比较行为后的短期死亡、人数优势变化等，不做未经支持的因果断言。
7. **检索证据：** 每项发现提供典型 Demo 片段、反例、样本量和适用条件。
8. **提炼训练建议：** 仅输出足够具体、适用范围清楚、普通玩家能实际执行的建议。

### 5.6 关键研究限制

- 职业选手前压/后撤的选择受位置、经济、战术职责、对手和队友配合影响；频率不能直接解释为优劣。
- 5v4 之后的每位 CT 玩家共享回合背景，不能视为完全独立的试验。
- 职业 Demo 可看到敌人真实坐标，但分析战术决策只能谨慎使用玩家当时有可能获知的信息。
- 首批 20–30 场用于验证管线和发现候选模式；强统计结论需要更多、跨比赛与战队的样本及独立验证集。
- 如果没有稳定规律，**严谨的否定结果也是有效产出**。

## 6. 标准研究交付物：行为规律卡

以后每项研究不再只输出一个指标，而要输出以下结构：

```markdown
# 行为规律：<名称>

- 状态：探索中 / 有初步证据 / 已复核 / 暂不支持
- 场景：地图、阵营、区域、人数、时间、支援条件
- 研究假设：...
- 行为定义：...
- 数据来源：比赛、Demo 数量、回合及玩家窗口数量
- 行为分布：...
- 结果比较：...
- 不确定性与可能混杂因素：...
- 典型片段：demo_id / round_id / tick 起止
- 反例：demo_id / round_id / tick 起止
- 对普通玩家的建议：...
- 练习方法：...
- 训练后如何验证：...
```

**示例假设（不是现有研究结果）：**

> CT 形成人数优势后，在缺少支援且处于高接触风险区域时，调整站位可能比持续无支援前压更有利于保持人数优势。

只有经过相似局势比较、人工核验，并明确说明反例与局限后，才能将其升级为较可靠的教学建议。

## 7. 两周执行计划

### 第 1 周：搭建最小研究数据层

- [ ] 盘点现有指标、实现位置、输入输出粒度和测试情况。
- [ ] 暂停新增基本功评分、排行榜等功能。
- [ ] 实现 CT 首次 5v4 触发点检测。
- [ ] 实现 5 秒行为窗口抽取与 `demo_id/round_id/tick` 可追溯记录。
- [ ] 为 Mirage 建立初版地图区域 / 前压后撤方向规则。
- [ ] 实现基础行为分类，支持 `unknown` 与置信度字段。

**交付：** 能从真实职业 Demo 批量生成结构化行为片段，并定位原始回放。

### 第 2 周：完成第一次研究闭环

- [ ] 处理首批约 20–30 场职业 Demo（按可获得的数据量灵活调整）。
- [ ] 抽样人工核验情境抽取和行为标签，记录错误类型。
- [ ] 在可比较的局势分组中统计行为分布及短期结果。
- [ ] 检查跨比赛、跨队伍样本差异和重要混杂因素。
- [ ] 选取有代表性的职业片段与反例。
- [ ] 生成第一张行为规律卡及一份简短研究报告。
- [ ] 明确结论的证据等级：初步支持、证据不足或不支持。

**交付：** 完整的「研究问题 → 数据 → 行为 → 对比 → 复核 → 训练建议/否定结果」闭环。

### 验收标准

**必须具备：**

1. 至少一种局势触发器和一种可复核的行为分类方式。
2. 每个研究样本均可追溯至原始 Demo 和 Tick 范围。
3. 有人工验证记录，不只依赖自动标签。
4. 结果包含样本量、分组条件、反例/异常情况和不确定性。
5. 至少完成一份行为规律卡：允许结论为「证据不足」。

**暂不要求：**

- AI 自动理解完整比赛；
- 全地图和全战术覆盖；
- 精美前端与统一玩家评分；
- 精确推断职业选手的真实心理意图；
- 仅凭观察性 Demo 宣称某种行为造成更高胜率。

## 8. 后续迭代次序

1. **扩大研究覆盖：** 在 Mirage 上增加补枪、清点与优势局势处理课题。
2. **提升上下文精度：** 地图枪线、可见性、信息事件、队友配合、角色与道具。
3. **对照普通玩家样本：** 相似局势下比较行为差异和适用性，避免照搬职业战术。
4. **引入大模型：** 仅将结构化证据及回放摘要输入模型，生成可追溯、带不确定性说明的训练解释。
5. **建设行为知识库：** 按地图、区域、局势、行为、证据等级检索规律。
6. **做训练效果评估：** 观察玩家在相关局势中的行为是否改变，及结果是否稳定改善。

## 9. 新增功能的立项门槛

新增任何指标、模块或可视化之前必须回答：

1. **它具体回答哪个游戏行为问题？**
2. **它验证哪一条可证伪的假设？**
3. **研究得出结果之后，普通玩家能够采取什么行动？**

如果三项答不清楚，就先不开发；如只是工程基础设施，则需说明它对哪项已批准研究具有必要性。

## 10. 当前决策摘要

- **保留**已有 Demo 数据与基本功指标，不推倒重来。
- **冻结**基本功评分体系扩展与复杂前端开发。
- **新增**局势建模、行为片段提取、相似局势比较和人工证据核验。
- **聚焦**第一个题目：Mirage CT 从 5v5 到 5v4 后的行为调整。
- **以一份可复核的行为规律卡，而不是更多指标，作为下一阶段里程碑。**

项目最终追求的不是「职业选手的数据画像」，而是持续累积可验证的 **情境—行为—结果—训练** 知识。
