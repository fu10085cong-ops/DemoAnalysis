状态：待做（**依赖 012（已完成）和 014**：用 014 的 `is_pro_player`。请先做 014）

## 目标

在 012 的程序汇总基础上，生成多场汇总的 AI 报告，讲清"这个人的习惯是什么、先练什么"。

多场汇总和单场报告是**两个独立的产品**，调用时没有从属关系（见 012）。但底层要尽量共用：

- 提交格式；
- 检查器；
- 诊断循环；
- 事实卡。

共用时，**单场的行为不能变**，用现有测试保证。

## 要做的事

### 1. 汇总摘要（`src/cs2coach/summary/digest.py`）

`build_summary_digest(summary, baseline, cfg) -> str`，依次包含：

1. **开头**：
   - 玩家用过的名字、场数、地图分布、在场回合总数；
   - 是职业选手时，加入 014 的固定说明。
2. **每场概况**：编号、比赛、地图、比分、击杀/死亡/助攻、在场回合、这一场的突出问题。
3. **整场枪法**：六项指标的各场中位数，用 `compare()` 和职业对比。注明"各场数值的中位数，共 N 场"。
4. **问题频率（汇总）**：012 的汇总频率表，包括出现场数、高于职业的场数、主要地图，并说明突出的判断规则。
   - 写明**稳定性**的含义："8 场中 7 场高于职业"比"只在一场集中出现"更能说明是习惯。
5. **检测到的问题**：
   - 每类启用的、有命中的非亮点问题：总次数、每场次数，以及最多 `[summary].representatives_per_problem`（配置，默认 3）个**代表性命中**；
   - 代表性命中的选择规则：
     - 尽量来自不同场次；
     - 同一场内，按偏离阈值的程度从大到小排列。偏离程度 = 证据和阈值中同名数值字段之比，例如 `ttd_ms` 对 `ttd_ms`；
     - 没有可比较的数值时按时间顺序；
   - 每条代表性命中写成一行：跨场编号，加上 `report/evidence.py` 生成的简短依据；
   - 亮点同样处理；
   - 开头沿用单场摘要的口径说明（出枪慢只能在打中过对手的交火中判断等）。

### 2. 工具

- `get_moment(match, moment_id)`：返回该场该瞬间的完整数据，以及它在该场的问题命中。
- `list_problem_hits(problem)`：返回这类问题在所有场次中的全部命中，包括跨场编号和简短依据，让 AI 能看到代表性命中以外的例子。
- 参数校验和错误提示照 `tools/queries.py` 的写法。

### 3. 提交格式与检查器

- **提交格式**沿用 `ReportSubmission`。`targets` 的 pattern 换成跨场格式：`^M\d+:R\d+(-(kill\d+|death|assist\d+))?$`。`submit_tool` 加一个参数来区分单场和多场，不要复制一份。
- **检查器重构**：把"按 target 取数据"的部分抽成可替换的解析函数，单场和多场共用其余全部检查。多场的解析函数：
  - 把 `M3:R9-death` 解析到第 3 场的瞬间和该场的命中；
  - 前提条件：在**该场**的 `ProblemReport` 中，有同编号、同 target 的命中；
  - 允许的数字：引用目标的数据；**整个汇总的数值**，包括汇总频率表、每场概况表、枪法中位数及职业对比、场数和回合数；
  - 敏感说法的谓词作用在被引用的瞬间上，与单场相同；
  - `id_in_text` 同样拒绝文字中出现的 `M3:R9-death` 这类编号；
  - "第 N 回合"必须是某个被引用目标的回合；"第 N 场"必须在 1 到场数之间。

### 4. 诊断循环

- 把 `diagnose()` 中与产品无关的循环抽出来，单场和多场共用：
  - 提交、拆开多套的一层、检查、退回修改、删除违规条目、替换总览、`raw_calls`；
  - 摘要、工具、检查器作为参数传入。
- 新函数 `diagnose_summary(summary, cfg, baseline, provider=None) -> SummaryDiagnosis`。
- 总览不合格时，替换成程序生成的一句话：场数、在场回合数、总击杀和总死亡。

### 5. 提示词（汇总专用）

在单场提示词的基础上改写，指标口径、准确性要求、讲解要求保持一致。另外强调：

- 重点是**跨场次反复出现的习惯**：优先讲汇总后突出、并且在多数场次都高于职业的问题。只在一场集中出现的，要说明这一点；
- finding 讲 1–2 个代表性瞬间，**最好来自不同场次**；pattern 列出各场的相关瞬间，讲共同原因；
- 不要逐场复述，单场的细节由单场报告负责；
- 训练计划按优先级排列，可以写成几周的计划。

### 6. 排版（`summary/render_report.py` 或在 `summary/render.py` 中新增函数）

1. 标题：`# 多场复盘：{玩家名} · {N} 场`，用过的名字，地图分布，模型名；
2. 总览（AI 写的）；
3. 突出问题表（程序生成）：包含出现场数、高于职业的场数、主要地图；
4. 关键问题：每条 finding 的每个目标，标注 `M3 · {match_id} · {地图}`，后面是该瞬间的事实卡（002 的函数）、检测依据、分析、怎么练；
5. 反复出现的问题：按场次分组列出相关瞬间；
6. 亮点、训练计划；
7. 附录：每场概况表；跳转命令表，列出比赛、编号、tick、命令。跳转命令要说明需要先在游戏里打开对应的 demo；
8. 末尾：职业样本来源；有删除的结论时写明条数。

### 7. 命令行

`summary` 新增 `--ai`：

- 写出 `汇总/report.md` 和 `汇总/submission.json`；
- 旧版本移进 `汇总/历史版本/`；
- 打印用量，格式和单场一致。
