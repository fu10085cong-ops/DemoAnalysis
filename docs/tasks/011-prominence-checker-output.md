# 011 突出问题的判断方式、检查器误杀、输出目录结构

状态：完成

## 目标

1. **突出问题改为按"多出的次数"和"偶然概率"判断**。产品负责人指出，现在按倍数排序，次数很少的问题权重过大。例如一场 30 回合的比赛：
   - "有道具却直接拉出"只有 2 次，因为职业很少发生，倍数高达 4.44×，排在第一；
   - "准星没提前放好"有 13 次，比职业多出 8 次，倍数只有 2.67×。
2. **修复检查器的两类误杀**，这是第二轮实测发现的。
3. **`analyze` 按"比赛 / 玩家"的目录结构输出**，重新运行时自动保留旧报告。

## 要做的事

### 1. 突出问题的新判断方式

对每类问题：

- **预期次数** λ = 职业频率 × 本场回合数。职业频率用基准中的 `hits / rounds` 精确计算，不用四舍五入后的 `per_10_rounds`。
- **多出的次数** = 本场次数 − λ。
- **偶然概率** = 泊松分布 P(X ≥ 本场次数 | λ)。意思是：如果这名玩家的真实水平和职业一样，单场里碰巧出现这么多次的概率。用 `math` 实现，**不要新增依赖**。
- **突出**：偶然概率 < `frequency_max_chance`（配置，默认 0.05），**并且**多出的次数 ≥ `frequency_min_excess`（配置，默认 2）。
- 职业频率缺失或为 0 时，与现在一样不判为突出，偶然概率为 None。

`FrequencyRow` 新增 `expected_hits`、`excess_hits`、`chance`，保留 `ratio`，只用于展示。

- **排序**：突出的在前；各组内按 `excess_hits` 从大到小。
- **配置**：删除 `frequency_min_hits`、`frequency_prominent_ratio`，换成上面两个新键，带中文注释。

参考数值（Claude 验算过，可以直接写成测试）：30 回合，职业频率每 10 回合 1.62，本场 13 次 → λ = 4.86，多出 8.14，偶然概率约 0.2%，判为突出。职业频率 0.15，本场 2 次 → λ = 0.45，偶然概率约 7.5%，**不**突出。测试中直接设定职业的 `hits` 和 `rounds`，让 λ 精确等于这些值。

### 2. 显示

- `_problems.md`、报告的"突出问题"表和摘要的"问题频率"一节，统一显示这些列：问题、本场次数、按职业频率预期、多出的次数、偶然概率（百分比）、倍数。
- 本场次数 > 0、但偶然概率 ≥ 阈值的，标注"次数较少，需要更多比赛确认"。
- 摘要中写明判断规则，让 AI 理解为什么倍数高的不一定是重点。
- 提示词中补充：
  - 优先讲突出问题；
  - "需要更多比赛确认"的问题可以提，但要说明样本少，不能作为主要结论；
  - 不要单独用倍数说明问题严重。
- `whole_match_numbers` 加入预期次数、多出的次数和偶然概率（百分比），让 AI 引用时能通过检查。

### 3. 检查器的两类误杀

1. **分位数名称**：数字紧跟"分位"，例如"75 分位"，或者写成 `p75`、`P90` 的形式时，只要这个数在配置列表 `[checker].quantile_labels`（默认 `[25, 50, 75, 90]`）中，就不做数字检查。
2. **舍入方式**：AI 把 0.125 写成"0.12"被拒，因为检查器只接受四舍五入得到的 0.13。改为：文字中的数字 x 有 d 位小数时，只要 |x − v| < 10^(−d)，也就是相差不到最后一位的 1 个单位，就算匹配。这样四舍五入、直接截断、银行家舍入都能接受。

### 4. 输出目录结构

`analyze` 输出到 `<--out>/<比赛文件夹>/<玩家名>_<steamid>/`：

- **比赛文件夹** = demo 文件名去掉扩展名；压缩包内的 demo 用包内文件名。
- **玩家名**中 Windows 不允许出现在文件名里的字符（`\/:*?"<>|`）和首尾空格，替换为 `_`。
- 文件名固定为：`report.md`、`facts.md`、`problems.md`、`moments.json`、`submission.json`。
- **重新运行时**：如果 `report.md` 或 `submission.json` 已经存在，先移到同目录的 `历史版本/` 下，文件名加上原文件的修改时间，例如 `report_20261016-0214.md`，再写新文件。`facts.md`、`problems.md`、`moments.json` 直接覆盖。
- 命令行最后打印输出目录的路径。
- 更新 README 中关于输出位置的说明。

现有文件夹会由 Claude 手工改成新的命名，**不要**去动 `data/output/` 下现有的文件。
