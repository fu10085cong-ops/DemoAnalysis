## 背景与决定（2026-10-19，产品负责人）

- 人工逐条判定行为耗时且不稳定，改为 **规则程序 + AI 各判一遍，人工只看两者不一致的窗口**，另从一致的窗口里每轮随机抽 5 条确认不是一起错
- 程序能直接从报点算出的（角色、去向、第一个人头是谁拿的）不交给 AI；AI 只判需要看过程和上下文的行为
- 试点只做 **交战后换位**；"试探回位"按位移和时间定义太粗、误判多，暂缓（见文末待设计）
- AI 拿到的信息要和选手在场上能知道的一致：**不给上帝视角**，不给回合结果
- 模型：先由 Claude 在对话里预演几条（不花钱），再用 `deepseek-flash` 跑，每条判 2 遍看稳定性；**真实调用前先征得产品负责人同意**

## 三个问题（CLAUDE.md 新增功能门槛）

1. 回答的行为问题：选手在首杀前后交过火之后，是换位、留在原位再架、撤离，还是继续压？
2. 可证伪的假设：交火后换位的选手，接下来几秒内被对手补掉的比例低于留在原位再架的选手（自己拿人头的 CT 10 秒内阵亡 32%，队友拿时 12%，`r01-v6`）
3. 普通玩家的行动：如果成立，"打完换位"有职业证据，可以给出练法（交火后 3 秒内离开被对手看到的位置）；不成立就记录为"不支持"

## 行为定义

**适用窗口**：触发（T 方首个阵亡）前 3 秒到后 10 秒内，该 CT 开过枪、造成或受到伤害、或击杀了敌人。

**交火段**：他的开枪、造成伤害、受到伤害、击杀事件，相邻间隔不超过 `gap_seconds`（1 秒）的连成一段。取包含触发时刻的那一段；触发时没有交火，就取触发后的第一段。**交火结束** = 这一段的最后一个事件。

**观察期**：交火结束后 `observe_seconds`（3 秒），可以超出 10 秒窗口；遇到阵亡或回合结束就截断，短于 `min_observe_seconds`（1.5 秒）判"看不出"。

**交火位置 F**：他交火的对手在交火结束时的位置。对手按优先级取：交火段最后一个事件里与他有伤害或击杀关系的敌人；没有就取交火结束时他看得到的最近敌人；仍没有就取他视线方向前方 1000 单位的点。

**标签**（P0 = 交火结束时他的位置，P3 = 观察期结束时的位置，d = 到 F 的直线距离）：

| 标签 | 规则基线 | 游戏里的意思 |
|---|---|---|
| 继续压 | d(P0) − d(P3) ≥ `push_min_closer`（150） | 朝刚交火的方向推进 |
| 撤离 | d(P3) − d(P0) ≥ `leave_min_farther`（250） | 往远离交火的方向撤 |
| 换位 | 以上都不是，且 \|P3 − P0\| ≥ `stay_max_move`（100） | 离开被对手看到的位置，换到另一个点 |
| 原位再架 | \|P3 − P0\| < 100 | 留在原位（转头看别处也算，依据里注明） |
| 看不出 | 观察期太短，或数据缺失 | |

阈值放在 `config/research.toml`（2026-10-21 前在 `default.toml`）的 `[research.fight]`，是待复核的工程假设。

## 选手视角时间线（交给 AI 的输入）

每个窗口生成一段中文文本，从触发前 3 秒到观察期结束，每 0.5 秒一行；开头写清地图、他的角色（T 阵亡时的报点、层级、防守区组）、第一个人头是谁拿的、局势（5v4、回合时间），并标出程序算出的交火结束时刻（AI 可以不同意）。

| 内容 | 依据 | 说明 |
|---|---|---|
| 自己：报点（层级 / 防守区组）、离 P0 多远、移动方式（静止 / 走 / 跑 / 静步 / 蹲）、正在看哪个报点、血量 / 护甲、武器 / 子弹、开镜、被闪 | 逐 tick 状态 | "看向"取视线方向角度最近的报点中心（本场所有玩家位置的中位数） |
| 看到的敌人：报点、距离 | 几何视野 `features/visibility.py`，扣除烟雾和被闪 | 只在看得到时出现 |
| 雷达上的敌人：报点 | `spotted_by_mask`，本队任一人发现 | |
| 听到的：敌人脚步 / 其他声音的方向（报点）和距离 | `player_sound` 事件，他在该声音的 `radius` 内才算 | 不计墙体隔音和声音遮蔽 |
| 队友：报点、血量、阵亡 | 雷达 / HUD | 每 1 秒一行 |
| 队友标点 | `player_ping` | |
| 事件：击杀信息（谁杀谁、武器，不含位置）、自己开枪 / 命中 / 受伤（伤害来自哪个方向） | 事件 | |
| 不给 | 没看到、没听到的敌人位置；回合胜负；之后发生的事 | 语音沟通不在 demo 里，开头注明"语音未知" |

## AI 输出

JSON：`{"label": "换位|原位再架|撤离|继续压|看不出", "fight_end_s": 数字, "evidence": "第几秒发生了什么", "confidence": "高|中|低"}`。提示词版本号写进结果文件。

## 试点样本与流程

1. `sample`：从 `r01-v6` 抽 40 个适用窗口：自己拿第一个人头 20 个、队友拿 20 个；同一回合最多一个，按比赛分散，固定种子
2. `timelines`：解析涉及的 demo（CPU 任务，开始前通知），生成时间线与规则基线，写入 `data/research/ai/<名>/`
3. Claude 预演：读几条时间线，检查信息是否够用、格式是否好读，必要时调整
4. `run`：征得同意后用 `deepseek-flash` 每条判 2 遍
5. `compare`：规则 vs AI、AI 第 1 遍 vs 第 2 遍的一致率和混淆矩阵；不一致的窗口 + 一致中随机 5 条生成人工复核清单（2D 回放页）

## 验收

- 时间线里没有任何该选手看不到、听不到的敌人位置（单元测试用合成比赛验证）
- 每个阈值在配置里；规则基线和时间线生成都有单元测试
- 输出一致率、AI 自身稳定性、人工复核后的规则与 AI 各自准确率；结论写回本文档

## 待设计：试探回位

按"走出去又回来"定义会误判：区域内调整角度、晃身拉枪、被闪后退、捡枪都会混进来。更好的方向是**视线试探**：移动后能看到原位置看不到的敌方区域、并朝那里看，之后回到看不到的位置。需要先定义"原位置看不到的敌方区域"并人工抽查，交战后换位跑通后再单独讨论。

### 第 5 版定义（2026-10-20 定稿第一版，阈值在 `config/research.toml` 的 `[research.stance]`，方向分组在 `[research.directions.de_mirage]`）
