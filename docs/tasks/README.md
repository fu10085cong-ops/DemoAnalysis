# 任务单

Claude 写任务单，GPT（Codex）按任务单实现，Claude 审查。协作规则见仓库根目录的 `AGENTS.md`。

## 流程

1. Claude 和用户确定方案后，新建 `NNN-简短英文名.md`（编号递增，从 `TEMPLATE.md` 复制），状态为"待做"。
2. 用户在 Codex 中指定任务单，例如："按 docs/tasks/001-xxx.md 实现"。
3. GPT 实现，跑通测试，填写"完成报告"，状态改为"待审查"。
4. Claude 审查工作区的改动（`git diff`），并实际运行测试或 demo 验证：
   - 通过：状态改为"完成"，用户确认后提交；
   - 不通过：在"审查意见"中逐条写明问题，状态改为"需修改"，回到第 3 步。

## 状态

`待做` → `待审查` → `需修改` ↔ `待审查` → `完成`

## 写任务单的要求（给 Claude）

- **验收标准要可检查**：写明具体的测试用例、命令和预期输出，不写"实现得好"这类无法检查的要求。
- **写清接口**：函数签名、数据结构、配置键名、输出格式。
- **写清范围外**：明确哪些不要做，防止顺手改动。
- **背景只列必须读的**：具体到文件和章节，不让 GPT 通读整个仓库。
- 涉及 demoparser2 字段和数据口径的结论，要写明已经验证过的事实和出处，不让 GPT 凭记忆猜。

## 两条任务线

| | 修补任务（`001`–） | 结构性任务（`S01`–） |
|---|---|---|
| 针对什么 | 一个具体的问题，例如某条规则漏了某种写法 | 一整类问题反复出现的原因 |
| 验收 | 指定的用例通过 | **先量出改动前的指标，再量改动后的**，用数字说明这一类问题少了多少 |
| 产出 | 代码改动 | 除了代码，还有一个能反复运行的测量工具，以后每次改动都能用它复查 |

2026-10-17 回顾时发现，修补任务里的问题大致分四类，对应四个结构性方向：

| 问题类型 | 例子 | 结构性方向 | 任务 |
|---|---|---|---|
| 程序检测误判 | R4 看见对手前的 11 发子弹被算成"压枪差" | 测量每条检测规则的准确率，并对全部 demo 做可疑组合扫描 | S01 |
| 口径和外部平台不同 | 补枪 3 秒对 5 秒、道具伤害用原始伤害 | 把平台数据固定成回归对照，口径一偏差就报错 | S02 |
| AI 说法写错 | "近距离 AK 对拼"、"慢主要在看见到开枪" | 检查器从黑名单改成白名单：事实性描述词只能来自程序占位符 | S03（待 S01 结果出来后设计） |
| 产品逻辑没想清楚 | 高光选了最慢的那次、▲▼ 并列全都标 | 流程约定（不需要单独写任务单）：凡是"程序替用户做选择"的功能，Claude 先用 5 场真实比赛手工走一遍、给产品负责人看过样例，再写任务单 | — |
